# Unity Assist Tools 更新履歴

## Release 1.4.2 Preview

### 概要

今回のアップデートでは、Project File Colorizerを中心に機能を拡張しました。

従来の拡張子による自動色分け機能を維持しながら、ユーザーが任意のアセットにカラータグを設定し、色別に分類・管理できる機能を追加しました。

実際のファイルやフォルダ構成を変更せず、異なる場所に存在するアセットを疑似的なグループとして整理できるようにしています。

---

### 1. 手動カラータグ機能の追加

Projectウィンドウから、ユーザーが任意のアセットにカラータグを設定できる機能を追加しました。

- 右クリックメニューからカラーを設定
- 8色のプリセットカラーに対応
- カスタムカラーの設定に対応
- 複数アセットへの一括カラー設定に対応
- 設定したカラータグの解除に対応

従来の拡張子による自動分類だけでなく、ユーザー自身の目的や用途に応じてアセットを整理できるようにしました。

### 2. カラーグループ機能の追加

設定したカラータグを利用して、アセットを色別に一覧管理できる機能を追加しました。

- カラーごとのアセット一覧表示
- アセット名・ファイルパスによる検索
- 一覧から対象アセットを選択・強調表示
- カラータグを利用した疑似的なアセット分類
- 一覧から対象アセットの場所へ移動・表示

実際の保存場所やフォルダ構成に依存せず、同じカラーが設定されたアセットをまとめて管理できます。

### 3. 既存の自動色分け機能との統合

従来の拡張子別自動色分け機能を維持し、手動カラータグと共存できるようにしました。

- 既存の9種類の拡張子別自動分類を維持
- 手動カラータグがある場合は手動カラーを優先
- 手動カラータグの解除後は従来の自動色分けに復帰
- 既存のカラー設定を維持
- 色分け機能のON/OFFに対応

### 4. 設定保存・データ管理の改善

手動カラータグを継続して利用できるよう、アセットGUIDを利用した管理方式を採用しました。

- GUIDを基準としたアセットとカラーの対応付け
- ProjectSettingsへの手動カラー設定の保存
- アセットの移動・改名を考慮した管理処理
- 設定保存時のバックアップ処理
- 保存後のデータ検証
- 保存に失敗した場合の復旧処理

また、カラータグの設定によってアセット本体、ファイル名、`.meta`ファイル、実際のフォルダ構成を変更しない設計としています。

### 5. 不具合修正

Release 1.4.1で発生したコンパイルエラーを修正しました。

- `EditorGUILayout.ColorField`の引数指定を修正
- `GUIContent`を使用する呼び出し形式に変更
- カスタムカラー設定画面のコンパイルエラーに対応

### 6. 動作確認結果

Unity Editor上で以下の機能について操作確認を実施しました。

| 確認項目 | 結果 |
|---|---|
| 拡張子による自動色分け | OK |
| 色分け機能のON/OFF | OK |
| 任意の色を指定したカラータグ設定 | OK |
| 指定タグによるアセットの分類・一覧管理 | OK |
| 一覧から対象アセットの場所へ移動・表示 | OK |

確認した範囲では、上記の操作に問題はありませんでした。

### 7. 静的検査・品質管理

ソースコードおよびパッケージ構成について、以下の検査を実施しました。

- package.jsonのJSON構文確認
- Assembly DefinitionのJSON構文確認
- 同梱`.meta`ファイルのGUID重複確認
- ZIPファイルの整合性確認
- 旧Release 1.3.0のバックアップが元ファイルと一致することを確認

今回の開発では、過去の正常動作版を基準とし、変更範囲をProject File Colorizerに限定しました。

Transform HelperおよびTexture Color Replacerのソースコードは変更せず、既存機能への影響を抑える方針を採用しています。

### 8. 今後の改善予定

- 大規模プロジェクトでの処理速度・安定性の検証
- 複数アセット操作時の安定性確認
- アセット移動・改名・削除後の設定維持に関する追加検証
- カラーグループの操作性改善
- 設定管理機能の拡張

**Release 1.4.2 Preview**

従来の自動色分け機能を維持しながら、ユーザーが自由にアセットを分類・管理・検索できる機能を追加しました。

実際のプロジェクト構成を変更せずにアセットを整理できることを、新たな特徴としています。

既存機能の非破壊性、操作性、動作速度および安定性を重視し、今後も段階的な改善を進めていきます。
